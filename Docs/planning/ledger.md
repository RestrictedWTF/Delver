# Feature Ledger

One row per feature. This is what makes it possible to **skip, fall back, or
revisit** anything at any point without re-deriving the context.

The **"Deliberately not done"** column is the load-bearing one. Six months on,
the question is never "does this work" — it's *"did we skip that on purpose, and
what did we know at the time?"*

## Status values

| Status | Meaning |
| --- | --- |
| `planned` | In the roadmap, not started |
| `wip` | Being built; see [STATUS.md](status.md) for where |
| `stub` | Interface exists, implementation is a placeholder |
| `done` | Built and used |
| `skipped` | Deliberately not built. **Reason required.** |
| `superseded` | Replaced. Link the ADR. |
| `removed` | Was built, then dropped. **Reason required.** |

## Falling back

Every feature is a contrib, so removing one is deleting a single import line
from `workbench.common.main.ts`. Set the row to `removed`, say why, and keep the
"deliberately not done" notes — that's the context a future revisit needs.

For ship-but-disabled, use a `delver.experimental.*` configuration flag rather
than a branch.

Its `status` filter is `all`/`undecided`/`accepted`/`rejected` and an unrecognised value is refused with `INVALID_ARGUMENT` rather than answered as `all`, because a fabricated complete answer to a question nobody asked is the worse failure. Each finding is paired with `findingDecisionFor`, so `decision` is absent exactly when a human has not reviewed it, and `undecidedTotal` is reported alongside `total`. It is marked `untrusted: true`, since finding text can quote sample-derived strings. `delver_reanalyze` re-derives every fact from the bytes plus the accepted corrections and takes no arguments, since it re-derives the whole image or nothing; before it, the only route to a re-derivation was authoring a correction to force one. It authors nothing and modifies no bytes but is priced as a write, because every cursor and table index issued before the call indexes a table that no longer exists — so it reports `generation`, which is what lets a stale cursor be refused rather than answered from the rebuilt table, and `decoding`, without which its counts are unqualified zeros on an unsupported architecture. It requires an attached sample; `functionCountObservedBefore` is restated from a pre-call listing so agreement with the server's own count is evidence rather than a tautology. `delver_export_report` renders the retained findings as Markdown through `delverFindingReport.ts`, a pure function of findings, decisions and tool-call records that reads no bytes and therefore works on a project opened without its sample. Findings are grouped by human decision, rejected ones kept because ruling something out is a result, unreviewed ones rendered as unreviewed rather than beside accepted conclusions, and every evidence citation resolved to its capability or shown raw with a note that the record is no longer retained. An empty report is a statement about the investigation, not about the sample. A report past the serialized limit is refused with its size rather than truncated, since a report cut mid-claim loses that claim's evidence. `delver_propose_type` also takes `target: "composite"` with `name`/`size`/`fields` in place of `address`/`declaration`; its schema is a `oneOf` rather than one object with optional fields, so a composite cannot be sent with an address that would be silently ignored. Authoring batches are bounded and fully validated before retention, work for offline projects, and never materialize before human acceptance. Accepted composites, data types, and prototypes form a versioned content-wide `schemaVersion: 2` semantic snapshot; memory and portable caches refuse other snapshots, and PyGhidra defines the composites and then applies the rest transactionally before decompilation. Session resolution, attachment checks, pagination, limits, cancellation, provenance, untrusted labelling, and per-stage latency measurements happen once for every caller. Adaptive pattern selection from historical sample bytes remains fail-closed until those bytes are retained or attached. A per-content-hash function index keeps focus resolution off the 178k-row snapshot parse. An *unresolved* call site forces `partial` on its own, so a direct call graph can never read as a complete list of what a function calls; a graph whose indirect sites all resolve to named imports does report `complete`. A negative path result is a claim about the program only when the search was exhausted with no limit hit and no unresolved site on the frontier; `proves_absence()` is that condition in code. Cross-references answer offline from the table retained in the project (schema v8), and a project that retained none refuses with `TARGET_NOT_ATTACHED` rather than reporting zero references. An xref result reports its source's true pre-cap `total` and exposes `sourceBounded`, so a capped list is `partial` instead of a confident count of what references an address. Global inventories intentionally remain partial after paging because only decoded static data references are observed.  `delver_decompile` pages a long function on line boundaries rather than cutting it at a byte offset with no way back to the rest: `nextCursor`, `firstLine` and `totalLines` orient the caller, `lineMappings` is scoped to the lines a page carries, and the cursor is bound to the exact text so continuing into a re-decompiled body is refused. `delver_list_strings` and `delver_search_strings` walk in two phases — an index into the list retained when the image was analysed, then a position in the image re-scanned through `analysis/scanStrings` once past it — with the cursor carrying which phase it is in, because an offset into a list and an address in an image are not the same number. One filter is applied to both phases, so a search cannot change its answer as it crosses the cap, and a filtered page scans on until it fills rather than handing back the first window's survivors. An offline project has only its retained list, so it still reports that strings were never extracted and no cursor will reach them rather than offering a continuation it cannot honour. **Deliberately not done:** structured immediate/constant search, vtable- and dataflow-derived indirect targets (the `probable` confidence tier), unions and enums (`kind` is a `struct`-only allow-list and the tool exposes no `kind` at all), local variables and stack frames, exact per-function semantic dependency stamps, and headless-backend type application | |
